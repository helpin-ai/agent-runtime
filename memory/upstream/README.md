# Upstream attribution

`retain-concise.txt` assembles the following constants, without paraphrasing, from
`hindsight-api-slim/hindsight_api/engine/retain/fact_extraction.py` at Hindsight
commit `017b3f5d888d67341e70f43c102cb8155bb9f51e`:

- `_BASE_FACT_EXTRACTION_PROMPT`
- `_DEFAULT_LANGUAGE_RULE` (with two trailing newlines)
- `_CONCISE_GUIDELINES`
- `_CONCISE_EXAMPLES`
- `CAUSAL_RELATIONSHIPS_SECTION`

The retain mission is empty. The language directive preserves input language.
`LICENSE` is the upstream MIT notice. The Go RRF implementation is derived from
`engine/search/fusion.py` in the same revision. See `docs/memory.md` for remaining
behavioral differences and the evaluation requirements.

`retain-schema.json` is generated from upstream `FactExtractionResponse` with
`openai.lib._pydantic.to_strict_json_schema`, preserving field descriptions and
nullable causal/attachment lists. The text-only Go extractor ignores attachment
indices. This does not add multimodal retention support.

`memory/chunking.go` ports the text, JSON conversation and JSONL chunking
algorithms from the same pinned `fact_extraction.py`, using the upstream
default 3000-character budget. Image-aware chunking is not implemented.

`memory/links.go` and the graph scoring in `memory/recall.go` derive from
`engine/memories/pg/links.py`, `link_expansion.py`, and
`engine/db/ops_postgresql.py` in this revision. SQLite uses exact cosine
searches instead of the upstream ANN probes.

`memory/scoring.go` ports the default recency, temporal and passthrough-rank
scoring from `engine/search/reranking.py`, without observation proof boosts.

`postgres-english.stop` is the English stop-word vocabulary shipped with the
PostgreSQL 18.1.0 reference installation (`share/tsearch_data/english.stop`).
It filters query terms before SQLite FTS5 matching to better align the English
search configuration; FTS5 Porter stemming/scoring still differs from Snowball
and PostgreSQL ts_rank.

`memory/retry_split.go` ports `_split_chunk_for_output_retry`; 56 differential
fixtures pin its text/conversation split behavior. Native adaptive recovery also
handles invalid structured output, caps recursion at three split levels, and
returns an error instead of silently dropping an unrecoverable fragment.


`Provider.EmbedFacts` ports `engine/retain/embedding_processing.py` date/entity
augmentation, with 36 differential fixtures. Extraction user messages match the
pinned Python timestamp formatting, with eight differential fixtures.
`KeywordText` includes the source context, entities and event-date signals used
by the upstream PostgreSQL search vector, while SQLite keeps its own FTS ranking.

`consolidation-system.txt`, `consolidation-input.txt`, and
`consolidation-schema.json` are generated directly from the same pinned revision's
`engine/consolidation/prompts.py` builders (default mission/language) and
`_ConsolidationBatchResponse` strict schema. The initial Go consolidation implementation uses these artifacts, while candidate
retrieval, deduplication and policy gaps are documented in `docs/memory.md`.


`reflect-system.txt`, `reflect-tools.json` and their mental-model variants are
built from the same pinned `engine/reflect/prompts.py` and `tools_schema.py`:
neutral default bank, mid budget, observations/raw recall enabled, optional mental
models, and source expansion disabled. The minute-resolution current date is
replaced by a runtime placeholder. The bounded Go agent reuses these instructions
and tool schemas, with stricter scoped evidence validation and documented
local-server finalization differences.


`memory/extraction_dates.go` follows pinned `_parse_datetime`'s
`dateutil.parser.isoparse` behavior for calendar/ordinal/week dates and ISO times,
with 53 direct upstream differential fixtures. Invalid model dates remain unknown
without rejecting the fact. Relative-date and point-event fallbacks apply only to
absent date fields, matching the upstream conversion order. Reference HTTP date
validation remains strict.

The derived-retrieval fixture executes pinned `interleave_fusion`,
`apply_combined_scoring`, and `_build_observations_for_llm` directly. It covers
four scoring pool sizes (1, 2, 50, 300), interleaved fusion, duplicate proof IDs,
and Unicode source-context truncation. `consolidation-dedup.txt` and its schema
come from pinned `_DEDUP_PROMPT` and `_DedupDecision`; all share this directory's
upstream MIT attribution.

`token-count-fixtures.json` was generated by the pinned Hindsight tokenizer's
`toktok._encoding("o200k_base").count`, covering Unicode, JSON, timestamps and
special-token literals. The Go default uses the same bundled vocabulary.
